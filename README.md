### 2026-11-03 设置内切屏后的玻璃恢复（当前修复，待安装）

本轮针对用户在设置中选择另一台显示器后玻璃再次消失的问题。此前双屏回归在关闭管理窗口时直接修改模型，遗漏了真实设置选择事件和“管理窗口仍打开、目标输出尚未缓存”这组条件。新增用例通过实际 ComboBox 的选择事件复现，旧实现会在等待新屏材质时超时。

原因是管理期间禁止实时捕获自有窗口，只能读取已保存的背景；首次切入另一个输出时却没有该屏幕的背景。旧刷新逻辑还会因为原矩形不再匹配而撤下材质，随后无法在管理期间补齐新输出。

修复后，设置切屏会启动独立的干净背景刷新事务：暂时排除本进程可见窗口并确认排除状态 → 在后台等待 DWM 合成更新 → 重建当前连接输出的背景 → 等待 GPU 复制完成后再释放捕获帧 → 恢复原截图状态 → 按新屏幕的坐标和 DPI 生成并提交完整材质。截图就绪状态要等到可见玻璃实际提交后才恢复。短暂失败保留完整画面并自动重试，不要求关闭设置或再点重试。

新增回归覆盖：设置窗口保持打开时首次切入冷缓存副屏；失败捕获的自动恢复；设置内“重试视觉效果”；连续四次来回切屏；日历独立选屏；分类在新屏幕展开；关闭设置后恢复实时采样。用红蓝生成背景逐项核对像素与输出归属，同时检查截图排除状态确实恢复。所有窗口回归仍在隔离桌面执行；真实后台检查不创建窗口、不访问用户数据库、不保存像素。

验证：Release 全解决方案零警告／零错误，核心 72 项、Windows 服务 23 项、隔离界面 154 项通过。报告 `artifacts/v2-ui-qa-20261103-152705`，DLL SHA256 `3EDC221B7C8DC5E09BEA866C962FB4C2A72CB9F1F7A7E694DDB90FACB3DD15EB`。同一发布 DLL 的真实后台检查成功刷新两块输出并生成完整材质，未创建窗口或保存像素。生成数据下约 61 秒／845 次切换，窗口 4→4、退出后 0；18 秒待机短样本约 553.79 MiB、整机 CPU 0.860%，性能仍未达预算，不作长期或真实桌面观感验收结论。

### 2026-11-03 玻璃完整帧与自动恢复（上一已安装版本）

用户反馈底栏、分类与日历的玻璃间歇消失，并出现色块错乱。本轮重新核对 GlassDesk 研究版本 `b1eb58c2d7205fca57e192e45d363872ced55624`，重点参考其完整位图所有权、材质状态校验、背景就绪与静态场景交接的处理方式；本仓库继续独立实现，没有复制其源码、着色器或品牌资源。

本构建隔离界面 147 项通过，报告 `artifacts/v2-ui-qa-20261103-150023`，DLL SHA256 `CC5F9041FA5CD0EE85B8AB3F33D82DAE402A53BDAA76174C0BD9F941A53FBEEC`。以生成的 500 入口／10,000 日程完成约 61 秒持续切换、1,008 次切换，WPF 窗口 4→4，退出后为 0；累计拒绝 16 个过期帧。相同发布 DLL 在本机两个输出的真实无窗口采样、完整材质读回、预乘色与位图独立所有权检查通过，未保存屏幕像素。18 秒待机短样本约 479.09 MiB、平均整机 CPU 0.608%，结束私有内存约 456.67 MiB；未达到原预算，不将此短样本或生成场景称为真实桌面长期验收。

此前生产路径把 WPF 的显示表面与会被后台复用／重建的共享显存绑定，遇到窗口移动、设备回收和异步结果交错时，撤掉旧画面与准备新画面不是同一个提交动作。现在生产路径改为：DXGI 按屏采样 → D3D11 裁剪、模糊与透镜处理 → 复用 staging 读回存储 → 创建拥有独立像素的不可变 BGRA 位图 → UI 校验后整体替换。WPF 显示的完整位图可以独立于 GPU 设备存活；旧实验中的 D3D9Ex／D3DImage 路径保留用于兼容研究，生产玻璃不再使用它。新路径有 GPU 读回与位图复制成本，不宣称零拷贝或已达到性能预算。

每帧同时携带捕获代次、窗口修订、所属显示器、物理矩形、DPI、主题和视觉质量。位置、主题、显隐或设备生命周期改变后，过期结果只丢弃并重新生成，不能覆盖当前材质。GPU 缓冲与输出格式变化会重建对应资源，未完整生成的内容不交给 WPF；临时失败保留完整画面，按输出独立重试，连续失败不会永久停止恢复，也不会让另一个屏幕一起丢失玻璃。

管理窗口显示前先冻结干净背景；管理期间不继续捕获可截图的自有窗口，但可用原背景重新生成移动后的位置。关闭管理后先恢复采样排除，再接入新背景。静态材质保留位图并回收表面资源；普通模式按约 15 Hz 上限处理变化，静态采样退避到约 150ms，移动／鼠标更新合并后及时处理。关闭效果、高对比或系统不允许透明时继续明确使用兼容底色。

新增回归直接核对生成像素：红蓝帧切换后旧位图不变色；迟到的位置／主题帧不能提交；连续四次捕获失败可自动恢复；管理冻结期间移动材质不采入自身；十二次分类展开与颜色切换在十五个内部采样点均无未初始化色块；双屏交换后红蓝内容保持正确输出归属；圆角透明度与预乘色一致。实际桌面检查只在内存中验证采样、GPU 材质与位图所有权，不保存捕获像素或像素哈希，不将用户桌面图像作为提交内容。

本轮只改视觉呈现与恢复，不导入／恢复用户库。用户正常退出后已保存完整恢复快照，更新同一安装位置及快捷方式并启动新版；安装指纹与上述验证 DLL 一致。安装前后及启动后的应用入口、分类归属与顺序、固定项、日历、设置和其他状态逐项完全一致，SQLite 校验通过；恢复点与完整核验记录仅保存在用户 recovery 目录。真实桌面的最终观感、锁屏／休眠／Explorer 变化及三十分钟耐久仍需针对当前构建单独验证。

#### 上一实现的玻璃链路（历史）

上一实现的链路是 DXGI Desktop Duplication → 按窗口位置裁剪 GPU 背景纹理 → D3D11 两次绘制 → D3D9Ex 共享表面／WPF D3DImage → 普通 WPF 图标和文字。玻璃窗口排除自身采样，避免递归残影；背景不变时保留静态帧，管理打开时冻结材质并允许截图。后台有采样轮询，不能把它描述为零开销或完全事件驱动。

原着色器把整块背景统一模糊，仅靠边缘距离场位移、白色高光和鼠标光斑模拟厚度。它没有完整的物理光线追踪，也没有证明真实桌面的最终效果达标。本轮保留中心背景细节，减轻模糊与过亮的边线，按 DPI 调整采样半径；分类／更多弹窗接入和底栏、日历共享的材质服务。管理、编辑和搜索仍使用普通清晰界面。

双屏定位采用目标屏工作区与物理像素边界，处理负坐标和混合 DPI；避免反复把 WPF 逻辑坐标写回另一块屏幕，引发二次缩放。每个实际承载玻璃窗口的显示器使用其所属 DXGI 输出和适配器，禁止把主屏纹理拉伸到副屏。底栏／分类使用底栏所选屏幕，日历独立选择，搜索随鼠标所在屏幕打开，对话框跟随拥有者屏幕。所选屏幕暂时缺失时回到主屏并保留原选择。

#### GlassDesk 源码研究

已拉取 [everlosttime/glassdesk-open-source](https://github.com/everlosttime/glassdesk-open-source)，研究版本 `b1eb58c2d7205fca57e192e45d363872ced55624`。本机源码位于仓库外 `../glassdesk-tools/reference/glassdesk-open-source`，本仓库没有复制其源码、着色器或品牌素材。

源码默认材质是 AndroidLiquidGlass／FrostedGlass 路径：`LiquidGlassSurface` 管理材质、背景就绪与生命周期，`GlassBackgroundLayer` 提供背景，`AndroidLiquidGlassRenderer` 缓存透镜采样映射，对背景做柔和模糊、饱和度／色调、边缘位移及高光／阴影；动态过渡另有 WPF 像素着色器。它还保留独立的 `LiquidGlassOptics`、BRDF／Fresnel 和色散等可选光学组件，不能把这些都说成默认同时运行。值得参考的是清晰度与模糊的平衡、背景与前景分离、稳定的几何映射、过渡画面保留，以及材质分层的调试能力。

### 日历与工作台

- 月历、每周四时段课表、按日任务、任务编辑、拖动改期/时段、无时间任务排序。
- 日期、可选时间、完成状态、优先级、分类颜色、备注；跨日期搜索及完成/逾期/重要筛选。
- 顶部拉绳点击展开迷你月历和所选日任务，支持任务完成、新建与打开完整日历，前台全屏时隐藏。

- 不包含云同步、订阅日历、重复任务、在线插件市场或全盘索引。

### 数据与恢复

- SQLite 事务存储，状态版本 1，单行 JSON 包含入口、分类、任务、设置和插件开关。
- 修改先复制集合，写入成功后替换内存状态并通知 UI；保存失败保留输入。
- 打开执行完整性检查；拒绝未来版本；损坏时保留原库并提供恢复入口。
- 每天首次修改前备份，保留最近 7 份；导入/恢复前另存恢复点。
- 恢复先构建新库，归档旧库和 sidecar，失败尝试回滚；桌面恢复记录独立于数据库。
- 导入旧 GlassDesk Data 和旧日历 calendar.json 仅读取源文件，支持去重与迁移统计；可导出日历或全部状态。
- 数据：%LOCALAPPDATA%\GlassBogo；安装：%LOCALAPPDATA%\Programs\GlassBogo；实验：%LOCALAPPDATA%\GlassBogo-Lab。
- 桌面收纳默认移入 %USERPROFILE%\桌面归档\yyyy-MM-dd-HHmm；独立清单存于数据目录 harvest/*.json。预览确认后移动，同名加序号、不覆盖；服务支持失败回滚和撤销，原位置被占用时保留归档项。普通引用管理与此流程不同；当前 UI 衔接缺陷须先修复。
- 独立恢复命令：GlassBogo.exe --restore-desktop；GlassBogo.exe --recover-data "备份.json"。恢复数据前退出原实例。
- GLASSBOGO_DATA_DIR 可指定隔离测试数据目录；不可让自动测试指向真实数据。

## 5. V2 实验、结论与下一阶段

实验命令：

    GlassBogo.exe --glass-lab --compat

官方背景请求 DWMWA_SYSTEMBACKDROP_TYPE=3。Accent 使用未公开接口，明确标为兼容实验，不等于官方 Desktop Acrylic。C 分层配方无 WindowChrome、无框架扩展，支持同一 HWND 上“仅透明 / 恢复模糊”。不能把 AllowsTransparency=true 当作万能解决方案。

## 6. 本地插件 SDK v1

插件是独立 EXE，宿主不加载任意插件 DLL；进程隔离用于稳定性，不是恶意代码沙箱。包内必须有 plugin.json，executable 为包内相对 EXE 路径，拒绝 .. 和链接目录。

    {"id":"glassbogo.focus","name":"专注小记","version":"1.0.0","apiVersion":1,"executable":"FocusPlugin.exe","capabilities":["card","page","command","entry-menu"],"subscriptions":["workspace.changed"]}

安装默认停用，查看来源/能力后启用。四类扩展：卡片、页面、命令、入口菜单。没有在线更新，卸载只处理插件包，不改入口、任务或原文件。

宿主通过 Plugin.exe --pipe <随机管道名> 启动；CurrentUserOnly 命名管道，UTF-8 每行一条 JSON。API 版本 1，请求 ID 原样返回，超时 5 秒；代码限制单行字符串长度 65,536 个字符，**不是严格的 UTF-8 64 KiB 字节上限**。

请求字段 apiVersion/id/method，可选 action/entryName。事件 method=event、action=workspace.changed，不发送全量任务/入口；主动调用入口菜单时才传选中入口名称。响应 id、view 或 error；view 有 title/text/actions，动作 id/label，最多显示 20 项。宿主统一自绘，不接受 HTML、脚本、任意 XAML 或嵌入窗口。

可见卡片订阅事件，250 ms 合并；卸载退订。取消、退出、故障、超时会终止会话并回收进程。示例 FocusPlugin 专注次数只存在当前会话。
