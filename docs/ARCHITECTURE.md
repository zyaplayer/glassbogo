# 架构与数据契约

## 模块

- `GlassBogo.Core`：不可变入口/任务记录、分类业务规则、SQLite 事务存储、备份恢复、日历规则、旧数据迁移。
- `GlassBogo.App`：WPF 界面、系统合成玻璃、原生托盘/显示器接口、快捷方式解析、桌面发现、图标缓存和插件进程宿主。
- `GlassBogo.PluginSdk`：不依赖 WPF 的版本化清单、管道协议与插件运行循环。
- `samples/FocusPlugin`：声明式卡片、页面、命令、入口菜单示例。

## 入口模型

Entry 保存 ID、名称、目标、类型、启动参数、工作目录及单个 CategoryId。普通路径按 Windows 路径不区分大小写比较，参数保留大小写；不同参数可创建不同入口。待整理分类 `inbox` 不可移除。

IEntryCatalog 只修改入口和归属。ILaunchService 只交给系统打开目标。IDesktopIntegration 只发现桌面直接条目、记录与恢复图标显示状态。不存在文件移动、删除或递归浏览接口。

桌面和开始菜单读取在后台执行，`.lnk` 在专用 STA 线程解析；目标探测和 Shell 图标提取不阻塞 UI。图标最多缓存 512 项，最多同时读取 2 项。分类弹窗缓存最多 24 个页面，数据变更时失效；每页最多 12 个入口。全部入口列表启用回收式虚拟化。

## 存储

数据库版本 1 使用单行 JSON 文档置于 SQLite 事务中。当前规模以 500 个入口、1 万个任务为基准；每次修改先复制集合，记录本身不可变，写入成功才交换当前快照并通知界面。取消或失败不会将未保存内容变成当前状态。

数据库打开先运行 quick_check；未来数据库版本拒绝降级读取。备份、导入和恢复文件均先校验。数据库恢复先构建新数据库，再归档旧数据库和 sidecar 文件；失败时尝试回滚原文件。原日历和原 GlassDesk 数据始终只读。

## 生命周期与性能

默认使用 WPF 软件绘制控件以减少原生图形资源占用，DWM 仍负责系统玻璃背景。设置可切换硬件加速并在重启后生效。

主进程单实例。主分类栏常驻，工作台与日历按需创建；关闭后移除事件订阅。分类弹窗复用 HWND，鼠标离开仅隐藏。无持续屏幕捕获，无待机动画循环，桌面通过 FileSystemWatcher 通知。

后台插件在用户打开对应界面时启动，界面卸载即停止进程与订阅。关闭重型界面后，空闲阶段进行一次受控内存整理，不在每次悬浮时强制 GC。

桌面隐藏恢复记录独立于数据库，避免数据库损坏使桌面无法恢复。正常退出、重启和独立恢复命令均使用同一恢复逻辑。

## 界面测试

DesktopHarness 使用 CreateDesktop + CreateProcess 的 lpDesktop 创建独立桌面，不调用 SwitchDesktop。SelfTest 仅使用生成的假数据，通过 WPF 渲染快照检查窗口；这些截图不包含 DWM 合成的真实桌面背景。实际玻璃观感、多屏物理布局、全屏程序兼容性仍需真实设备验收。
